# Tasks and sprint plan

All items below are proposed and unassigned. The team can adjust scope and divide work according to availability. Complete the minimum viable path first; add extensions only if the sources and ratings are sound.

## Before the main experiment

- [ ] Agree on the research question, scope, authorship expectations, target track and division of work.
- [ ] Check event guidelines, submission requirements and deadline on the [official page](https://apartresearch.com/sprints/ai-x-epistemics-research-sprint-2026-11-13-to-2026-11-15).
- [ ] Read the PNAS prior work and check for closer or newer research; document the distinction without claiming unverified novelty.
- [ ] Check model access, version disclosure, expected cost, rate limits and permissions to use any prior team materials.

## Workstream A — cases and references

- [ ] Select 8–12 documented cases or a smaller verified set if time is limited. Record the number of independent source cases and paired variants separately.
- [ ] Include positive controls, partial matches, no sufficient supplied option and underspecified requests.
- [ ] Define the claim, decision, candidate information, critical requirements, acceptable answers and primary sources for each case.
- [ ] Independently review case definitions and resolve ambiguities before the main run.

## Workstream B — evaluation and responses

- [ ] Finalize the baseline and structured-check prompts, matching source information and requested output fields.
- [ ] Pilot on separate cases; freeze the main protocol and log changes.
- [ ] Run two model configurations where possible, twice per condition and prompt; randomize candidate order and preserve run metadata.
- [ ] Record failures and incomplete responses. Do not fabricate or silently omit results.

## Workstream C — annotation and analysis

- [ ] Apply the pre-defined rubric and, where feasible, independently review responses blind to model and condition.
- [ ] Record disagreements, adjudications, uncertainty and both correct and incorrect recommendations.
- [ ] Compare conditions on matched cases and report numerators, denominators and source-case-level uncertainty.
- [ ] Analyze at least one decision consequence using verified comparable public results; state its assumptions and avoid claims about actual adoption.

## Workstream D — report and submission

- [ ] Write the problem, related work, method, results, limitations and contribution; make a clear distinction between evidence and interpretation.
- [ ] Prepare a reproducibility package with cases, sources, prompts, versions, scores, analysis and a data/license statement.
- [ ] Review the report and submission material as a team and submit according to the official sprint rules.

## Suggested weekend sequence

**Friday:** agree on scope, complete source and novelty checks, select initial cases and pilot the protocol.

**Saturday:** freeze cases and prompts, run assistants, independently rate responses and investigate sourced decision consequences.

**Sunday:** complete analysis, check disagreements and limitations, write the report and prepare submission materials.

## Minimum viable result

A smaller, well-documented set of cases; reproducible model responses; source-backed ratings; one worked decision example; and an honest report. If assistants perform well, or the intervention does not help, document that outcome. A larger dataset, software tool or broad prevalence claim is not required for the minimum viable result.
