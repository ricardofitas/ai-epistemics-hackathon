# Research progress and next experiment

Updated 2026-11-12. All work here predates the sprint and is exploratory.

## Verified position

| Work | Observed result | Supported interpretation |
| --- | --- | --- |
| CivilComments recommendation pilot | 16 responses; both blinded agent raters: 0 unsupported | Correct recommendations on four guided claim variants in one configuration |
| MC2 implementation-recommendation pilot | 8 responses; both blinded agent raters: 0 unsupported | Correct response to changing numerical input requirements with code supplied |
| MC2 numeric stress test | Incorrect finite scores and NaN reproduced | Known implementation defect; exact prior fixes predate this work |
| Public-model trace audit | 12,255 item-run rows; no numeric-underflow effect above 1e-12 | No observed practical underflow impact in this bounded third-party sample |
| Lighteval label-gap audit/replay | 2/817 original records structurally affected; 28/12,255 replayed scores differ above 1e-12 | Known label-handling defect reaches real inputs; measured mean effect tiny and no checkpoint-order change |
| PNAS archive baseline comparison | Exact run prompt/mapping not recovered | Provisional file inconsistency only; do not count as confirmed assistant failure |

The project currently has **no verified new wrong recommendation** in its own sampled responses. It also has no basis for a claim of systematic assistant hallucination. The implementation cases are useful known-positive controls and reproducibility examples; they should not carry the main novelty claim.

## Next steps, in order

1. **Build the main case set from realistic research requests.** Use 6–8 independent source cases, covering direct fit, partial fit, unavailable evidence and missing information. Freeze critical requirements and acceptable qualified answers. Ask ordinary research questions without supplying the answer-revealing metric distinctions or full defective code used in these pilots. Keep these pilot cases outside the main set.
2. **Collect recommendations in fresh contexts across at least two configurations/interfaces.** Preserve exact versions/settings where exposed, full prompts, sources/retrieval access, final answers and failures. Match evidence across baseline/structured conditions. The current inherited-agent interface alone cannot support cross-model conclusions.
3. **Rate blind and connect any actual error to a decision.** Use the recorded rubric with independent human review where feasible. For a verified inappropriate recommendation, calculate its consequence using comparable source results; report successes, uncertainty and null results too. CivilComments and HANS already supply conditional decision examples if a matching recommendation failure is later observed.
4. **Choose the paper's claim after inspecting those results.** If errors occur, describe their conditions and decision consequences. If advice remains appropriate, report the boundary of success and the lack of evidence for the initial failure hypothesis. Retain known evaluator defects as controls or appendix material.
