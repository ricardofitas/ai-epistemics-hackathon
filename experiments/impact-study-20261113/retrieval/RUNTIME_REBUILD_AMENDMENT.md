# Runtime rebuild amendment before candidate scoring

The v2 first launch stopped before scoring on the official minus-one qrels markers. Its corrected v2 protocol was prepared but never used for candidate scores. In this workspace the pinned official `usnistgov/trec_eval` v10.0 source archive has the expected SHA256, and all 121 tracked source blobs match the published Git tree. GCC 14.2.0-19 and the unchanged `make` command produced a different unstripped executable SHA256 from the earlier environment. Debug information embeds the local compilation directory; the precise cause of every binary difference is not established. We therefore pin the new exact executable and build receipt as v3 before scoring. The original v2 protocol, build receipt and freeze-ready note are preserved byte-for-byte under `v2_before_runtime_rebuild/`.

No candidate, qrels, source URL, source byte pin, metric, split, statistical test, random seed, threshold, evaluator code, or output rule changed. The official quicktest passed; the evaluator's 28 synthetic checks passed, including minus-one treatment and a 126-candidate ingestion fixture. All 127 official source files were independently restored against their original hashes before scoring.

The v3 protocol and build receipt must be published and their Git bytes verified. A separate Git commit SHA, timestamp and exact protocol SHA are supplied to the evaluator only after that publication. Results from this replay illustrate the known nonsignificance-versus-equivalence mistake; they are not evidence that actual TREC-COVID researchers combined mismatched qrels, changed model choice, or suffered real-world harm.
