# Full-options replication of the GAMMAF v2 live experiment

Protocol ID: `gammaf-v2-full-options-20261115-v1`.
Source commit: `94cc84d54df5f8df83a9470d035d94860a05d6cf`.
Prepared before any requests from this repaired experiment. The frozen
`artifacts/repaired_manifest.json` is authoritative for the panel and settings.

## Question and claim

Does earlier blocking plus the existing notices change delivered correctness
relative to terminal filtering when agents see the complete answer options?
The original live experiment omitted the text mapped to each option letter.
This study repairs that stimulus while retaining the existing policies. It is
a repaired-stimulus replication on an already selected panel, not an independent
test of generalization and not a search for favorable examples.

## Frozen design

- Source population: the same 64 questions for which the reconstructed original
  attack target equals the gold label (28 MMLU, 21 CSQA, 15 MMLU-Pro).
- Select 32 by SHA-256 ordering over protocol ID, task and question ID, within
  fixed task quotas: 14 MMLU, 10 CSQA, 8 MMLU-Pro. Selection never uses answers
  generated by the repaired experiment or its correctness, votes or flags.
- Chain and star, the original per-question seed, three original insiders,
  original fixed wrong target, ten agents, three rounds.
- Two arms only: `GAMMAF-FixedTarget-PostHoc` and `EpistemicGuard-Inline`.
  Sixty-four paired settings and 128 arm-debates are planned.
- Qwen3.8-27B, temperature 0.7, 1,024 output tokens. The existing one-shot
  answer-format fallback remains in place and is separately counted as a
  physical request. Full labels and option texts appear in every question prompt.
- Round-one content-addressed completions are shared when prompts are identical.
  A new output directory, cache namespace and manifest guard prohibit importing
  answers generated from the old letter-only stimuli.

## Outcomes and uncertainty

The primary outcome is paired delivered correctness: count recovered correct
answers, lost correct answers, both correct and both incorrect. Report bounds
on the net change across every planned pair, admitting every possible outcome
for missing arm-debates. A failed API call is not scored as a wrong answer.

Additionally report the complete-pair estimate and a separately labeled
complete-question estimate. The 95% percentile bootstrap resamples whole
questions within tasks, retaining both graph settings. Its interval applies
to the complete-question estimate, not to a differently selected complete-pair
estimate. No equivalence conclusion is made from an interval that includes zero.

Fixed-population vote transitions are a secondary diagnostic supplied by the
separate recount. They must include all initially non-malicious agents and
fixed round opportunities; missing observed votes are explicitly reported.
The original gated switch metric remains a separate historical comparison.

## Role knowledge and scope

The existing inline notification code uses simulator role identities to address
honest agents, and its blocking and notification interventions remain bundled.
This role knowledge is retained and disclosed. Terminal-vote rollback is not
an extra live arm. These results do not isolate blocking from notification,
remove the oracle advantage, or establish effectiveness in deployed systems.

## Execution limits and traceability

The live SDK has internal retries disabled. A persisted outer ledger counts
every physical request before transport, including failed requests and retry
attempts; interrupted pending attempts remain counted and conservatively
reserved on resumption. Limits are 4,500 physical attempts, 100 credits under
the pinned token-rate estimate and six elapsed hours including resumed runs.
Requests start at least five seconds apart, with up to four in flight. The
credit reservation uses UTF-8 prompt bytes plus framing allowance and the full
requested completion budget; these are conservative planning rates, not a
claim to reproduce the provider's invoice.

Every request stores the complete prompt and its hash, response text and
separate reasoning/content when available, usage, status and timestamp.
SQLite completion caching and arm checkpoints support resumption. A mock run
tests the harness only and is stored separately from live results.

The selection and analysis are frozen before live calls. Any later change is
versioned and disclosed; result direction is not a stopping or inclusion rule.
