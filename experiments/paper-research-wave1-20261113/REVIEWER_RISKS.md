# Constructive reviewer risks and claim bounds

Prepared 13 November 2026 from the earlier `RESULTS.md`/`coverage-after.json` and this wave's `EVIDENCE_LADDER.md`, `ladder.json`, and `study/protocol.json`. This review did not inspect new-wave responses, API artifacts, credentials, or performance-pilot outputs. It changes no response criterion or primary label.

**Assessment:** the design can support a narrow paper about a reproducible audit of benchmark-based scientific advice, with selected-case recurrence and transparent limits. Twenty-one source-backed families, if actually completed and reviewed, would strengthen coverage; three fresh requests per selected cell can establish observed recurrence under recorded settings. Neither number establishes representative prevalence, independent cross-domain replication, or a general model ranking. An actual PAWS/HANS pilot could add one measured decision example. A null consequence result would still leave a viable recommendation-audit contribution.

|---|---|---|

Report every prespecified cell and all four labels, with attempted and scorable counts. | **Family/benchmark count inflation** | Maintain a one-row-per-source-claim-family inventory with completion status and domain cluster. In the reviewed material, 15 is observed; 21 is conditional on six new families receiving interpretable answers; 25 is a future target. Repeats, wording probes, alternative names and the consequence pilot add zero recommendation families. | Say “source-backed recommendation case families,” not “21 independently executed performance benchmarks” or 21 independent domains. Do not pool 119/126 heterogeneous historical captures into an error rate. |
| **Synthetic illustration versus measured impact** | Keep the logical PAWS illustration explicitly synthetic. For an actual pilot, freeze candidate eligibility, data bytes/splits, scoring and adapters, target construct, tie rules and every planned comparison before candidate scores are read; report every eligible candidate and all nulls. Keep target evaluation separate from selection evidence. | A measured selection change and target-score difference support only that candidate/data/protocol example. No change is an informative test result. Neither result alone proves user harm, a benchmark defect, or a general causal effect of bad advice. |

These are requirements for particular assertions, not a demand to stop reversible sampling until every issue is solved. The first five largely require faithful reporting and adjudication of work already planned.

## Next: highest-value strengthening after the current block

1. **Finish the descriptive analysis before adding calls.** Display per-cell primary labels and same-mechanism counts, transport/completion outcomes, and case-cluster summaries. Preserve correct advice, qualified proxies, uncertainty and nulls. Report operational missingness by configuration without treating it as substantive error.
2. **Use the PAWS feasibility pilot as a bounded test.** If the prespecified recurrence gate is met, apply one fixed candidate set and one prespecified adapter to the selected PAWS data and the independent role-sensitive NLI target. State that different datasets/tasks can change rankings for several reasons; the pilot demonstrates a consequence of the two evaluation choices for these candidates, not a uniquely identified causal mechanism. Report target-score differences and uncertainty for the actual sampled unit, including invalid task outputs. If the gate is not met, report “not run under the prespecified gate.”
3. **Characterize two more contexts if useful.** Prefer the ladder's fixed two-request extension of all 12 original selected cells. If resources require an adaptive subset, state its rule and keep the three-context and extension results separate. This increases description precision; it does not turn a selected sample into a representative one.
4. **Check wording transfer separately.** Fidelity-review and freeze the unused probes before sampling. Report both probes and all configurations. Transfer supports those selected wordings; it adds no new source families and does not establish natural-query prevalence.
5. **Make specificity visible without changing the rubric.** Use already collected aligned/qualified answers in the human review sample and show how bounded proxy use is accepted. Document false-positive concerns and disagreements, rather than adding mandatory answer details after seeing outputs.
6. **Verify the incremental contribution with primary related work.** Position the paper around the audit design, observed advice patterns, recurrence and reproducible artifacts. Distinguish a new instance of a known misconception from a new failure mechanism. Add the remaining four families only for genuinely new coverage and review capacity, not to meet an arbitrary headline count.

## Defer: required only for claims the present paper need not make

- A probability sample of real scientific queries, larger repeated samples and a separate inferential estimand are needed for population prevalence or a stable model ranking. They are not prerequisites for a selected case-study paper.
- A user-adoption study is needed for real-world harm claims. An actual ranking reversal is needed only for a ranking-reversal claim; it is not mandatory for an audit paper.
- An autonomous retrieval arm or balanced evidence intervention can be a later study. A supplied source package tests the complete evidence/instruction package; it cannot by itself establish a browsing-specific effect.

**Proposed bounded claim:** “We audit curated, source-backed scientific-evaluation recommendation cases, document material unsupported conclusions under a frozen rubric, and test whether selected mechanisms recur across fresh requests under recorded model configurations.” Append an actual-candidate consequence statement only if that separate test has been completed, with its exact positive or null result. Use the attained family count and human-review status at manuscript freeze.
